A registry that keeps its receipts

Declare once.Prove per crate.

incan.pub is where Oven's build facts become publications. It holds what a crate's build.rs would have discovered as declared, bound records — so Oven can compile the crate without ever running the script — and it keeps, for every binding, how firmly that declaration has been proven.

Why incan.pub exists

A build script is a question. The registry publishes the answer.

Under RFC 119 Oven never executes build.rs. What the script would have probed — compile-time flags, generated inputs, linked libraries — is declared instead. Upstream crates don't ship that declaration, and the answers are constants only under one exact toolchain, target, profile and feature set. Somebody has to publish them, per selection, with provenance.

01 · DeclarationA fact is bound, not guessed.

Each record names the compiler, target, profile and features it was derived under. libm enables optimizations_enabled above opt-level 1, so its release and debug records differ — and a consumer applies neither to any other selection.

02 · ProvenanceHarvest is observation. Publishing is declaration.

Cargo observes what a script emitted on one machine; a reviewable step turns that into a registry fact. The evidence — receipt, Cargo lock digest, Cargo version — travels on the event.

03 · ProofReal is a status you can read.

A binding is harvested until an Oven-baked unit is shown byte-equivalent to Cargo's; then it is attested. That word is on the index line, per binding, before anything is downloaded.

The innovation is not hosting manifests for other people's crates. It is making a build fact a first-class publication — with an identity, a binding, evidence, and a status — so that "Oven is real" is something a consumer can check per crate rather than take on faith.

What is not in it

No environment
libm's script reemits CFG_OPT_LEVEL for its own test logging. Nothing compiles against it, so it is not a fact. There is no key to put it in.
No source
The registry never mirrors a .crate. It names one by checksum and confirms crates.io publishes that checksum for that version.
No guess
proc-macro2 answers proc_macro_span only under RUSTC_BOOTSTRAP. A harvest that ran with ambient state is not a fact of the toolchain, and its record does not carry that answer.
proposedA harvest emitted it.

Observed by the compatibility publisher on one machine. Nothing has been published yet; a reviewer sees the evidence and the environment the harvest ran under.

harvestedThe registry admitted it.

A fact event exists. The binding is on the index line and a consumer may select it — and, while both paths coexist, cross-checks it against what Cargo observed.

attestedOven reproduced the bytes.

An attest event names an Oven-baked unit whose RFC 124 identity equals the Cargo-built unit's. This is where "real" stops being an adjective.

“
The registry is a notary, not a judge.

It cannot know that a cfg answer is true. It verifies form, binding, authorisation and immutability, and it stores references to the three places truth actually lives: the harvest evidence, the attested asset, and the consumer's own cross-check. Trust is a policy the consumer sets — accept harvested, or insist on attested.

Interim boundary

Small by design. Explicit by default.

incan.pub today publishes external-source records for the crates the 0.6 standard-library closure needs. It does not yet claim:
  • source Loaf publication, scopes, or ownership beyond the toolchain-operated crates-io scope;
  • baked-asset storage or distribution;
  • signatures beyond the git commit, or a served checkpoint;
  • a home for a script-emitted value that a compilation does observe — a typed constant is the open question;
  • the link and tool publisher-side work of RFC 119, reserved until their grammar exists.
Those belong to RFC 125's signed form and later 0.6 slices. If a record cannot honestly bind a consumer's selection, the consumer is told so and stops.
